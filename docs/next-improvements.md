# 后续改进优先级

2026-11-02。依据本仓库的当前代码与 1023 SOG 实测，不包含 TEZOI 改动。

## 1. 已完成：SOG 原生紧凑 CPU 模型

查看器默认使用显式 packed model，Worker 与 renderer 直接接受 DC、标签和调色板，
并分段写入 GPU 映射区。解析 API 默认 canonical `model.sh` 保持兼容，
可通过 `toCanonicalModel()` 显式展开。紧凑模型有独立的形状、有限值和标签范围校验。

完整场景模型数组 743.8 → 203.8 MB，消除完整 576 MB SH 分配，净减 540 MB；
另省去 59.8 MB CPU 上传拼接数组。四次交替加载的六组完整图像哈希一致。
主线程/Worker V8 backing-store 采样与分阶段耗时见 [加载报告](1023-sog-loading.md)。
该采样不包含浏览器原生分配与驱动内存，不等于整个进程的峰值。

## 2. 分页 GPU 存储，降低单缓冲区能力门槛

`setModel()` 当前要求单个 projected buffer 为 96×N bytes，300 万点仍为 288 MB。
因此即使设备总显存足够，单绑定上限为 256 MiB 时也无法加载。
这对兼容性比再减少约 0.1 ms 的排序更重要。

建议先针对 SOG 路径分页存储属性和投影数据。着色器按全局 Gaussian ID 选择分页，
排序与透明合成仍保持全局深度顺序；不能把各页分别排序并直接混合。
根据 adapter 的单绑定、单缓冲区和每阶段 storage binding 数量共同选择布局。
达到绑定数量上限时需要明确回退或报错，不能仅按总显存估计能否运行。

验收：用显式低 requiredLimits 的设备配置覆盖 128/256 MiB 单绑定上限，
检查所有页边界、稳定排序、跨页透明遮挡和零可见点。实际硬件兼容性仍需真机测试。
分页首先解决单绑定限制，本身不保证降低总显存。

## 3. 真实漫游轨迹与浏览器 CPU profile

已有六个固定视角验证不能代表移动中的 p95/p99、交互延迟或长时间稳定性。
应增加确定性相机轨迹，覆盖转向、进出房间、近相机大 Gaussian，以及连续切换分辨率。
先记录整帧 p50/p95/p99、GPU 各阶段、可见数量、浏览器 CPU 编码/提交与事件响应。

当前针孔帧包含 28 个 compute pass 和两个 render pass；GPU 主要阶段约 0.9–1.3 ms，
同步墙钟常见约 4–5 ms。这个差值也包含同步、驱动与调度，不能全部归因于 JS。
只有 profile 确认命令编码占比较高后，才选择减少 pass、缓存可复用命令或减少分配。
任何 pass 合并都必须重新验证 storage 写后读同步与图像一致性。

## 4. 空间分块与更便宜的全量可见性判断

首版 GS pinhole / orthographic 保守块剔除已完成，详见 [空间分块报告](1023-spatial-blocks.md)。
3M 点夹具中约 86–89% 跳过精确投影，排序图像与基线一致；新增索引内存和加载耗时。
鱼眼、全景、GUT 的块范围、候选块间接 dispatch 与 Worker 构建仍未实现。
以下保留为此方向的原始动机与后续边界：

虽然只排序约 1.4–4.8 万点，当前每次移动相机仍投影全部 300 万点，约 0.42 ms。
更大模型或较弱 GPU 上这部分会更突出。可先按空间建立块级 bounds，剔除整个不可见块，
然后对候选 Gaussian 精确投影；最后再考虑 LOD 与按需加载。

Gaussian 的块 bounds 必须包含有限 alpha 支撑，而不只是点中心，避免大尺度/细长点漏绘。
先独立实现不降质的块剔除，再单独评估 LOD 的误差，避免把两种收益混在一起。

## 5. 条件性后续：tile 前向合成与其他相机

当前固定针孔视角的 GPU 绘制只有约 0.3–0.75 ms，暂不足以证明值得重写 tile renderer。
如果轨迹、鱼眼或全景测试显示绘制再次主导，再考虑分块候选列表、前向合成和遮挡提前终止。
这涉及顺序、支撑范围、临时内存和峰值容量，不能只添加一个透明度判断。

另可评估 SuperSplat 风格的运动期间随机透明采样，停止后恢复排序。
它减少排序与混合开销，但需要真实深度、噪声控制和独立拾取策略；
先做可选分支并用纯 3DGS/GUT 连续轨迹验证收益，见 [随机渲染评估](stochastic-rendering.md)。

## 建议实施顺序

紧凑 SOG CPU 表示已完成，接下来优先 **GPU 分页兼容 → 真实漫游与 CPU profile**。
这些阶段保留当前默认画质。空间分块、LOD、Float16 或额外量化应各自独立验证，
不以降低点数或精度掩盖管线问题。每阶段继续仅修改 WebGS，TEZOI 同步单独安排。
