# 随机渲染：分层采样、空间重建与时间重投影

2026-11-02。基于已有随机渲染分支增加去噪，默认完整排序不变。
查看器的“交互加速”中新增去噪选择：**空间 + 时间重投影 / 仅空间重建 / 关闭**。
选择交互加速后，默认空间 + 时间重投影；原始采样可随时用于比较。

## 方法与边界

- 每个 Gaussian、每帧、每个 2×2 像素组使用随机排列的四个 alpha 阈值分层。
  每个像素仍保持边际均匀分布，避免同一组对平滑透明度同时全保留或全丢弃。
- 空间阶段使用 3×3 tent 重建。随机深度本身会跳变，深度差权重限制为 0.5–1，
  不使用强 bilateral 截断来保留本应消除的噪点；输出同时估计局部平均命中深度。
- 时间阶段按当前深度反投影为世界坐标，再投影到上一帧；四个双线性 tap 分别校验
  深度。采用相对 10% 容差接受随机平均深度的波动，历史至少有 25% 有效权重才混合。
- 对历史颜色做当前 3×3 邻域 min/max 约束，历史年龄最多 8，历史权重最多 0.85。
  没有命中支持、投影越界、深度不一致时直接使用当前空间结果。
- 实现 pinhole、orthographic、fisheye、equirectangular 的反投影与上一帧投影，
  全景在空间邻域和历史 tap 处做水平方向周期寻址。GS 鱼眼深度为中心 view Z，
  GUT 鱼眼为射线峰值距离，不能混用。

这是一套有偏的重建预览，不是离线无限采样估计器；平均随机深度并非真实网格表面。
10% 深度容差、邻域颜色约束均为抑制拖影的启发式，无法保证任意透明层或细结构完全无拖影。
目前实景仍有可见噪声，尚未达到“移动画面和排序输出相同”的程度。

## 历史与生命周期

模型替换、输出分辨率变化、sorted/raw/spatial 与 temporal 切换时清空历史；
内参、镜头、畸变、背景、过滤、方法、尺度等配置改变时拒绝旧历史。
视线方向变化超过约 25.8° 时整帧拒绝旧历史；平移通常通过逐像素深度/越界检查拒绝。
底层调用者可用 `resetHistory:true` 明确标记任意相机剪辑跳转。
默认静止恢复排序、标定输出、截图均绕过去噪并重置历史，精确输出没有改变。

深度纹理由 discard 改为 store 供重建读取。空间输出/深度为 12 bytes/pixel；
时间颜色/深度/年龄双缓冲再增加 32 bytes/pixel。单独使用空间模式时不分配历史纹理。
完整时间模式相对原始随机帧新增纹理 **44 bytes/pixel**：
960×540 为 **22.81 MB**，1440×810 为 **51.32 MB**（十进制）。
含原本随机 depth32float 时为 48 bytes/pixel，不含现有颜色目标、截图和镜头射线缓存。
新增 176-byte previous camera uniform；这些资源已纳入 `getMemoryUsage()`。
纹理按需分配、缓存复用，resize / dispose 时释放；只运行默认排序不会分配重建纹理。

## 完整 300 万点实测

同一 1023 SOG，RTX 5090 D v2 / Edge 156；三组局部平移与转向轨迹、两种方法、
960×540 与 1440×810。每条路径连续预热 8 帧，再采样 24 帧；时间阶段不能与
排序帧交错执行，否则历史会被清空。计时显式等待 GPU，不包含图像 readback。
四条路径分组执行，受系统负载和执行顺序影响，不是严格配对的 CPU/GPU 调度实验。

质量另行完整运行相同轨迹，逐帧用对应排序输出作参考。MAE 为 RGB 的平均绝对
字节误差，数值越低越接近排序输出；同时包含噪声、深度顺序差异、滤波偏差和模糊。

| 方法 / 宽度 | 原始随机 MAE（三视角范围） | 空间 MAE | 空间 + 时间 MAE |
| --- | ---: | ---: | ---: |
| 3DGS / 960 | 21.99–27.59 | 10.74–13.19 | 10.04–11.69 |
| 3DGS / 1440 | 21.98–27.57 | 10.74–13.17 | 10.04–11.66 |
| GUT / 960 | 16.56–23.01 | 7.82–11.40 | 7.26–10.20 |
| GUT / 1440 | 16.56–23.01 | 7.82–11.37 | 7.26–10.15 |

最终误差相对原始随机帧减少约 **54–61%**。边缘区域 MAE 也下降，但不等于细节无损：
原始随机噪声本身会使梯度虚高，所以报告保留了梯度比，却不把它作为清晰度分数。
空间重建仍会软化约 1 像素尺度的边缘。

GPU timestamp 的新增空间 + 时间 pass p50 合计约 **0.024–0.047 ms**；
不包含深度 store、分层阈值改变对 raster 的影响，也不包含驱动原生分配。
同步墙钟 p50：完整排序约 **3.9–5.1 ms**，原始随机 **3.0–4.1 ms**，
空间 + 时间 **3.0–4.7 ms**。部分组不比完整排序快，例如 GUT 960 view1
为 4.0 → 4.3 ms，不能承诺默认开启总能提高帧率。
这些是高端 GPU 上的短轨迹结果，不代表手机、长时间运动、全景实景或其他场景。

每组恢复排序后的完整 RGBA8 最大字节差为 **0**；六组 GUT 静态相机的哈希仍匹配
去噪加入前提交的加载基准。完整计时/质量样本见
[机器记录](benchmarks/1023-reconstruction.json)。

## 细节和拖影检查

确定性合成测试：一条接近像素宽度的红色 Gaussian 细线，16 帧去噪后中心峰值
相对排序保留 **68.65%**，停止后的精确截图逐字节恢复。这说明移动预览确有细节对比度损失。

另一测试在绿色背景前放红色前景，移动相机露出背景后连续检查 8 帧：
旧红色在检查像素上的最大残留 **1/255**。另覆盖显式 reset、内参/背景改变、
模型替换、奇数分辨率、排序 resize 后返回旧尺寸、四种相机的噪声下降与精确截图。
这只验证这些遮挡夹具，不能证明任意透明场景没有鬼影。

## API、复现与产物

```js
element.setRenderingMode('movement');
element.setReconstructionMode('temporal'); // 'spatial' / 'none' 可对照
renderer.render(camera, {
  transparency:'stochastic', reconstruction:'temporal',
  resetHistory:false, // 相机剪辑跳转时设为 true
});
await renderer.readPixels({exact:false}); // 去噪后的预览
await renderer.readPixels(); // 仍为完整排序精确截图
await renderer.readTimings(); // spatial_ms、temporal_ms 仅在执行时非零
```

`GaussianViewer` 构造参数支持 `{reconstruction:'temporal'}`，只影响交互随机帧；
renderer 默认 `reconstruction:'none'`，兼容原始随机帧 API 与固定 seed 测试。

```powershell
npm test
npm run test:sog
npm run test:gpu
node scripts/benchmark-reconstruction.mjs --frames 24 --output test-results/reconstruction-final
# 可通过 --methods / --widths / --views 缩小验证范围
```

脚本输出四宫格 PNG：sorted / none / spatial / temporal，最后一帧对应相同移动相机。
本机产物位于 `test-results/reconstruction-final/`；它与完整原始图像不纳入 Git。
默认排序画质依旧保持，后续应优先真机评估、稳定深度估计及更好的采样策略，
再决定更高质量的运动预览是否值得增加样本或更复杂的时间滤波。
